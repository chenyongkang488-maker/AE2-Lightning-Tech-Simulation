# 多方块模拟室外观与 UI 改造方案

日期：2026-10-02。状态：用户已要求拟定后直接实施，含补充 UI 要求。目标环境保持 Minecraft 1.21.1 / NeoForge 21.1.252，基于 alpha.9。

## 目标与方案选择

按用户五张参考图重做粉白外壳、成型后的连续边框/玻璃/顶盖、中央像素能量球，以及与边框融合的控制器和原版过载接口。球体只在实际加工时出现；模拟熔炼模块使球体变橙色并取消原火焰。

推荐“静态连接外壳 + 控制器动态渲染”的混合方案。Blockbench 负责可编辑的零件、纹理和动画图层，客户端模型按结构位置拼接，控制器渲染器负责能量球、电弧和心电图。

只改 PNG 无法解决重复封边和纵向横条；把整台外壳全部每帧动态绘制虽可实现，但不利于区块渲染缓存和玻璃排序。因此外壳使用缓存的静态模型，只有动态内容逐帧绘制。

## 结构规则

| 部位 | 新规则 |
|---|---|
| 外尺寸及水晶容量 | 3³～7³、9/16/25/36/49 个，保持原规则 |
| 12 条边及角 | 模拟室框架，底部非角边允许一个控制器及最多一个原版过载接口 |
| 顶部整面 | 模拟室框架；成型后为连续顶盖 |
| 四个侧面中部 | AE2 聚能石英玻璃；成型后为无边框粉白透明玻璃 |
| 底面内部 | 框架或原有效率、时运、过载、熔炼模块 |
| 内部 | 空气，视觉内容不占用世界方块 |

每个尺寸的侧面玻璃数量变为 `4 × (N−2)²`，顶面不再接受聚能石英玻璃。框架边沿和顶盖内区分开判定，升级模块仍只允许放在底面。

旧 alpha.9 存档使用玻璃顶的结构暂停并提示“顶部需要模拟室框架”；解体时恢复原玻璃，玩家更换顶面后重新成型。保留控制器库存、输出、费用和已付款任务，不自动将玻璃变成框架。恢复后的已付款批次继续使用原快照。

## 外壳与玻璃

未成型框架参考天枢外壳的嵌套金属框、角部扣件和内凹面板设计，重新绘制乳白主体、浅灰阴影、粉色细线；深色仅用于凹槽及屏幕。建议壳体 32×32 像素纹理，保持 Minecraft 像素边缘。

成型模型依据结构局部坐标区分直段、端部、转角、顶盖中心及控制器/接口位置。同一个结构的各类方块共享接缝与线条坐标：

- 水平边中段不重复绘制左右封边。
- 竖边中段不重复绘制上下封边或横向色带；沿竖边方向绘制连续饰线。
- 只有真正的外角和边端出现收边与扣件。
- 顶盖中心拼成一整块面板，可加入一个粉色中心图案；不绘制逐格边框。
- 取消相邻同面玻璃之间的侧边几何与描边。透明中心仅保留低对比度、可连续平铺的反光纹；侧面整体略内陷，边缘由结构外框收口。

“无缝”不仅是相邻材质颜色相同，也要求相邻 UV、线条、几何和光照一致。玻璃采用区块中的薄平面模型，避免把所有透明内容叠成多层；检查斜视角和内外视角的排序及闪烁。

## 中央像素球与运行状态

外部展示由多颗水晶改为一个立体能量球，实际完美水晶继续保存在控制器库存参与生产。采用有阶梯轮廓的体素球壳，不使用始终朝向玩家的平面图片。

球体分三层：不透明核心、像素能量流纹、轻微透明外辉光。Blockbench 制作球壳和粉/橙两组流纹，建议 16 帧动画；流纹通过纹理图集动画播放。客户端额外做慢速旋转、微小浮动和亮度呼吸，外辉光通过透明外层模拟，不依赖光影包。

球体直径默认约为内腔宽度的 55%，随 3³～7³ 缩放并限制在内腔中。球体亮度自发光，但不为了动画反复修改世界光源。

| 状态 | 中央效果 | 控制器屏幕 |
|---|---|---|
| 未成型 | 无 | 黑屏 |
| 已成型待机、缺资源或输出等待 | 无 | 平直待机线及状态点 |
| 普通实际加工 | 粉色像素球、四角电弧汇聚到球面 | 粉白动态心电图 |
| 熔炼实际加工 | 橙色像素球，不绘制火焰 | 动态心电图 |
| 过载实际加工 | 在当前颜色球体外围叠加动态电环 | 动态心电图 |
| 过载与熔炼同时加工 | 橙色像素球及动态电环 | 动态心电图 |
| 网络离线、结构失效或必要区块未加载 | 无，停止工作特效 | 可加载时显示对应停机状态 |

颜色和过载电环以实际正在执行的已付款批次为准；本轮中途修改底面模块不会使显示与真实收费/产物不一致。工作状态通过现有服务器运行标志同步，动画相位由客户端时间计算，不逐帧发送网络数据。

## 控制器与原版过载接口

控制器未成型时为白色外壳，朝外一面是黑色屏幕和粉色边框。成型后壳体及线条使用对应的底部边框直段，屏幕像嵌在连续边框中，不保留一个突兀的独立方块边框。心电图局限于黑色屏幕内部，建议独立动画图层，实际加工时滚动播放。

原版 `ae2lt:overloaded_interface` 保留真实 BlockEntity、库存、频率、菜单、网络节点及掉落。已核对当前 2.1.0 的方块模型为普通 `cube_all`，适合在客户端包装已有模型。只有属于已成型模拟室的位置使用融合外壳与小型粉色接口标识；外部单独放置的接口及其物品模型继续使用原外观。

客户端维护按世界和控制器身份划分的成型位置缓存。模型的 `getModelData` 读取所属结构及局部位置，模型包装器输出融合几何；不依赖原接口新增服务器属性，也不把接口替换成代理方块。成型、解体、区块加载/卸载和资源重载时清理缓存并刷新相关区块模型，保证拆除后恢复原皮肤。

自有方块优先使用自定义模型加载器；包装原版接口模型只承担兼容层。缓存数据以不可变快照供区块渲染使用，不在每帧扫描结构。

## UI 建议

世界中的黑色控制器屏幕与玩家打开的容器界面是两套素材，分别制作。容器界面保留 alpha.9 的左右输入/输出、49 个水晶位、128 格四页输出和正常堆叠取出规则。

自动按已成型外尺寸 N 排列左侧 N×N 个水晶槽，即 3×3～7×7，而不是原有九列排列。未成型时显示状态并保留可访问的七阶库存恢复视图；结构缩小后如有超出容量的水晶，显示回收视图入口，额外槽位只允许取出。

进度条移到水晶和产物之间，采用竖向粉色进度条。输出保持每页 32 格（八列四行）、四页及每格 1024。隐藏 HV/EHV 库存总量，包括原来的数量悬停提示；配方消耗作为独立费用信息保留在诊断提示中。无需再轮询网络提取接口查询 HV/EHV 总库存。

删除玩家物品栏左右的矩形空白，背景改为上方机器区域较宽、下方九列玩家物品栏较窄的连续面板轮廓，两侧透明。机器上部宽度随水晶阵列变化，最高七阶界面仍适配 854×480。乳白/浅灰背景、灰紫文字、粉色进度条；数量标签保留描边，1024 不被图标遮挡。

这一版以换肤和状态表现为主，不扩大背包界面，不增加影响原交互的装饰层。

## 预期实现范围

1. Blockbench：重画未成型框架/控制器，制作连接框、顶盖、融合接口面板及粉/橙球体分层工程。
2. 结构判定与指南：顶面框架、四面玻璃，新错误提示和旧玻璃顶迁移说明。
3. 静态模型：成型局部坐标、横竖连接、顶盖与无边玻璃；原版接口条件换肤。
4. 动态渲染：删除多水晶外部展示及火焰，加入单球、动画颜色、球面电弧与屏幕心电图。
5. UI 皮肤和状态显示，随后再打包下一版测试原型。

生产周期、FE/HV/EHV 费用、倍率、任务保存、1024 缓冲和 AE 导出维持 alpha.9 语义。数据包结构材料扩展仍需更新顶面规则的说明，不改变库存及已付款任务保存格式。

## 验收

- 3³～7³、四个控制器朝向，横边/竖边/转角无重复封边；顶盖无逐格接缝，四侧玻璃无格子边框。
- 控制器与原接口和所在框架饰线连续，接口原菜单、频率、网络与掉落功能正常；未加入模拟室的接口外观不变。
- 普通、熔炼、过载、两模块共存及停机的视觉状态准确；球体具有真实体积，橙色模式无火焰。
- 旧玻璃顶暂停及材料恢复正确，换顶后任务继续，不重复收费或重抽产物。
- 区块重载、资源重载、断网和破坏结构不遗留球体或接口换肤。
- UI 在小窗口和不同 GUI 缩放下不裁切；数量显示及左/右/Shift 取出保持原行为。
- 多台 7³ 机器实测渲染开销，不用逐块动画实体；外壳使用缓存几何，远处减少动态细节。
