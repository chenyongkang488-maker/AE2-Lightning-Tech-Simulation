# 粉白机械约束器与多方块外观更新

目标版本：Minecraft 1.21.1 / NeoForge 21.1.252，模组 0.2.0-alpha.4。
用户已要求直接实现；继续使用现有开发工作树，保留旧布局和库存兼容。

## 设计

- 新约束器使用两层 7×7 激光框架底座，控制器位于上层正面中间。
  以控制器为原点，forward=FACING.opposite、up=basisUp(forward)，底座占
  right=-3..3、forward=0..6、up=-1..0；控制器替代 (0,0,0)。
  球心在 forward*3+up*4，原半径3的框架/玻璃体素球保持不变，球体最低处为 up=1。
  原球体底部的控制器位置改为框架，正面光口仍位于球心-forward*3。
- 使用独立持久化布局标记。已存在且没有该标记的约束器继续使用原球形布局，
  保留粒子、燃料和计时，不因外观升级触发解体爆炸。新放置的控制器使用底座布局。
- 成型球体保留像素/多边形轮廓，机械环具有分段白色装甲、螺栓、散热口和粉色导光条。
  底座正面控制器可直接操作；光口与其它功能方块保持实际碰撞和交互。
- 单块玻璃使用白粉边框，成型玻璃仅采样图集透明中央区，淡粉色且不带方格边框。
- 光点由已存粒子数驱动，零粒子不出现，至少一粒子出现一个光点，最多96个光点。
  光点沿球体内部几条倾斜轨道运动，具有短尾迹。关闭生产不影响已有粒子的显示。
- 发射器、四种矩阵、偏折矩阵与坍缩核心沿用分段装甲/导光/通风细节；原模拟室
  保留矩形无缝外框，在边角加入同风格的机械饰件，不改生产规则。

## 实现边界与接口

- 服务端负责 LaserStructureGeometry、LaserMachineBlockEntity、LaserAutoConstruction、
  LaserDemo、相关 GameTests。提供 host.structureTemplate() 与 host.receiverPedestalLayout()，
  客户端只调用这些接口，不写入资源/存储状态。
- 客户端负责 LaserRenderer、ReceiverShellVisuals、机械网格/粒子纯函数与测试、
  MultiblockSimulationRenderer。隐藏仅限所成型机器自己的 FRAME/GLASS。
- 图集由 Blockbench 原生绘图脚本导出。新增 tile32装甲、33通风、34螺栓、35导光、
  36状态灯、37底座顶面、38底座侧面、39支撑。tile4 为带边框玻璃，成型内区 UV：
  像素(66.5,2.5)~(77.5,13.5)，纹理图集128×128。原 tile0..23 尽量保持。
- 根任务负责图集、静态模型、文档、所有 Gradle 命令、Blockbench/客户端验收和安装。
  工作线程不运行 Gradle、不操作原生应用、不提交共享工作树。

## 执行与验证

1. 针对新底座/六面朝向/旧布局持久化/自动搭建编写回归测试，先验证失败，再实现。
2. 为粒子数量与可见性编写纯函数测试，检验零/少量/满容量/边界数据。
3. Blockbench 绘制新图集，生成匹配的可编辑 bbmodel 与 Minecraft JSON。
4. 实现客户端机械饰件、成型玻璃与粒子动画，覆盖块卸载/重载的隐藏注册。
5. 运行单元测试、可选 Mek/神秘农业/AppliedFlux 综合 GameTests、资源/发布检查。
6. 游戏内检查新结构自动搭建、控制器可交互、旧约束器升级不解体、粒子数量和同风格设备。
7. 本地 Git 记录与版本标签；仅替换 PCL 测试实例中的本模组 JAR，并备份上一版。
