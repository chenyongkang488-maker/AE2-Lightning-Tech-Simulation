# 0.2.0-alpha.18 验证记录

偏折矩阵的结构检查、连通图和光路方块观察使用变化驱动缓存。实际方块提交（包括自动化、指令和放置回滚）、接口模式、启停、增量、设备替换、区块生命周期及扩展注册使相关缓存失效。原生隐形光源与空气互换不使光束自我失效。每 20 tick 的材料／FE／闪电结算仍独立执行，来源停用与回调中的光路变更保留原有复核。

连续批次不再先同步空光束或临时降低多输入的显示强度。相同控制值重复提交也不清空光束；加载区块检查按结构涉及的不同区块采样。真实接口变化和障碍仍会撤销失效路径。

终极破坏模块在正常 `BlockDropsEvent` 中补齐基岩和 `ae2lt:firmament_conversion_core` 的一个自身物品；已有相同掉落不重复添加，取消掉落、禁用方块掉落及创造模式规则仍有效。苍穹转换核心在主世界放置后开放原生加工，其他维度保留原生星舰判定。原配方消耗、输出空间和处理时间不变，不增加自然战利品初始化。前置 2.1.0／2.1.1 的 `canProcessHere` 方法和原生配方实际加工均已核对。

63 项数值配置中，37 项安全上限翻倍，26 项物理／协议／整数／前置或已忽略限制保留。所有默认值、下限和键保持一致。新上限同步至组件 codec、机器 NBT、网络读取、加工校验及中英文提示。旧存量降限继续保留；无容量标记的旧存档仍使用旧默认容量验证。参数列表见 `docs/MACHINE_CONFIGURATION.md`。

- `alpha18-behavior-red.log`：稳定光束、重复重建、基岩掉落及主世界加工四项回归失败。
- `alpha18-warmed-continuity-red.log`：把光束夹具移至原生延迟加载完成后，再单独恢复旧批次清空方式；两次真实批次回调观测到空光束，确认问题并非初始化清理。
- `alpha18-final-new.log`：120 项 JUnit，无失败／错误／跳过；497 项必需 GameTest 全通过；构建、源码 JAR 和版本校验成功。NeoForge 21.1.255、AE2 19.2.18、AE2LT 2.1.1、Thunderbolt 2.0.2，含 Applied Flux、Glodium、Mekanism、Mystical Agriculture 和 Cucumber。
- `alpha18-final-old.log`：测试实例对应 NeoForge 21.1.252、AE2 19.2.17、AE2LT 2.1.0、Thunderbolt 2.0.0，含同组可选集成；497 项必需 GameTest 全通过。

- `alpha18-instance-before.json`：替换前 74 个其它模组、配置和启动器文件的 SHA-256 基线。

新增 8 项 GameTest 覆盖缓存结构与方块变更、稳定批次显示、原生主世界 40 tick 加工、取消终极掉落、40G FE 真实物品序列化、更高接收储量保存及降限、2G 强化选择保存，以及 2,097,152 并行提交 8,589,934,592 件产物。现有多输入汇总、回调取消、来源移除、光路生命周期与资源守恒检查全部继续通过。

五项资源验证均通过：制造配方、工作站、多方块、激光和超限水晶。最终主源码构建和安装哈希记入 `0.2.0-alpha.18-install.json`。仅本地提交／标签，未远程发布。用户继续手动检查游戏效果，本次未自动操作 Minecraft，也未宣称客户端视觉验收。

主源码检出的 `.mcmeta` 按仓库规则使用 LF，与前置的 CRLF 仅有换行差异（154／162 字节）；解析后的动画元数据完全一致。超限水晶验证器据此比较完整 JSON 数据，继续严格校验帧顺序、时间及 PNG 亮度／轮廓，不把文本换行当成动画变化。
